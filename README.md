# StringPlus

Собственная реализация части стандартной библиотеки `string.h` на чистом C, дополненная набором своих функций и полноценной реализацией `sprintf` с поддержкой флагов, ширины и точности.

Написана без сторонних зависимостей (кроме `check` для юнит-тестов), покрыта тестами, сверяющими поведение с оригинальными функциями стандартной библиотеки.

## Возможности

### Реализация стандартных функций `string.h`
- Поиск: `s21_memchr`, `s21_strchr`, `s21_strrchr`, `s21_strpbrk`, `s21_strstr`
- Разбиение строки на токены: `s21_strtok`
- Сравнение: `s21_memcmp`, `s21_strncmp`
- Копирование: `s21_memcpy`, `s21_strncpy`, `s21_strncat`
- Заполнение памяти: `s21_memset`
- Длина строки: `s21_strlen`, `s21_strcspn`
- Тексты системных ошибок: `s21_strerror` (с раздельными таблицами под Linux и macOS)

### Собственные дополнительные функции
- `s21_to_upper` / `s21_to_lower` — приведение строки к верхнему/нижнему регистру (возвращают новую строку)
- `s21_insert` — вставка подстроки в произвольную позицию
- `s21_trim` — обрезка указанных символов по краям строки (пробелы по умолчанию)

### Собственная реализация `sprintf`
`s21_sprintf` — полная реализация форматированного вывода в строку с поддержкой спецификаторов `%c`, `%d`/`%i`, `%u`, `%f`, `%s`, `%x`/`%X`, `%o`, `%p`, `%%`, флагов (`+`, `-`, ` `, `#`, `0`), ширины и точности (включая `*` для передачи их через аргументы), а также модификаторов длины `h`, `l`, `L`.

## Требования

- GCC с поддержкой стандарта C11
- [check](https://libcheck.github.io/check/) — библиотека для юнит-тестирования на C
- `lcov` / `genhtml` — для генерации отчёта о покрытии тестами (опционально)

Установка зависимостей на Ubuntu/Debian:

```bash
sudo apt install check lcov
```

## Сборка и запуск

Собрать библиотеку, прогнать тесты и сгенерировать отчёт о покрытии одной командой:

```bash
make
```

Это выполнит по порядку:
1. `clean` — очистка предыдущей сборки
2. Сборку статической библиотеки `s21_string.a`
3. Сборку и запуск тестов
4. Генерацию HTML-отчёта о покрытии тестами в директории `out/`

### Отдельные команды

Собрать только статическую библиотеку:

```bash
make s21_string.a
```

Собрать и запустить только тесты:

```bash
make test
./test
```

Сгенерировать отчёт о покрытии (после запуска тестов):

```bash
make gcov_report
```

Отчёт откроется в браузере из файла `out/index.html`.

Очистить все артефакты сборки:

```bash
make clean
```

## Использование библиотеки в своём проекте

Подключите заголовочный файл и слинкуйте статическую библиотеку:

```c
#include "s21_string.h"

int main(void) {
    char buf[100];
    s21_sprintf(buf, "Hello, %s! You are %d years old.", "World", 25);
    // buf: "Hello, World! You are 25 years old."

    char* upper = s21_to_upper("hello");
    // upper: "HELLO" — выделено динамически, не забудьте free()
    free(upper);

    return 0;
}
```

Компиляция:

```bash
gcc your_file.c -L. -l:s21_string.a -o your_program
```

## Особенности реализации

- Функции, работающие с указателями на константные строки (`s21_strchr`, `s21_strstr` и т.д.), корректно обрабатывают `NULL` на входе, возвращая `S21_NULL` вместо падения.
- `s21_to_upper`, `s21_to_lower`, `s21_insert`, `s21_trim` выделяют память динамически (`malloc`) — вызывающий код обязан освобождать результат через `free()`.
- `s21_strerror` использует отдельные таблицы кодов ошибок для Linux и macOS (через `#ifdef __linux__` / `#elif __APPLE__`), поскольку тексты системных ошибок отличаются между платформами.
- `s21_sprintf` реализован через собственный парсер спецификаторов формата (`parsing`) и отдельные функции форматирования под каждый тип (`format_d`, `format_f`, `format_s` и т.д.), без использования `vsnprintf` или других функций стандартной библиотеки форматированного вывода.

## Тестирование

Тесты написаны с использованием библиотеки `check`. Каждая функция сверяется бок о бок с оригинальной функцией из `string.h`/`stdio.h` на одинаковых входных данных, включая граничные случаи (`NULL`, пустые строки, отрицательные числа, максимальные значения типов).

```bash
make test
./test
```

Результаты также пишутся в `report.log`. Покрытие тестами можно посмотреть после генерации отчёта:

```bash
make gcov_report
```
